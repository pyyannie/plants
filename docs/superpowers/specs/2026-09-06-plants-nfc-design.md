# 植物施肥记录 NFC 应用 — 设计文档

日期：2026-09-06
仓库：`pyyannie/plants`（public）
线上地址：`https://pyyannie.github.io/plants/`

---

## 1. 要解决的问题

家里 15 盆以上植物，记不清哪盆上次什么时候施的肥、施的什么肥。

目标体验：**用手机碰一下花盆上的 NFC 贴纸，立刻看到这盆植物的施肥档案，并能一键补记一笔。**

---

## 2. 硬约束

这些是系统层面的限制，方案必须绕开，不是可以商量的取舍。

| 约束 | 后果 |
|---|---|
| iOS 快捷指令的 NFC 自动化只能读芯片 UID，读不到写进芯片的内容 | 不走快捷指令，改为把网址写进芯片 |
| iOS 不允许 NFC 芯片里的网址无确认自动打开 | 碰完需要点一下顶部横幅，无法消除 |
| GitHub Pages 免费额度不支持 private 仓库 | 仓库设为 public，因此不放任何敏感信息 |
| GitHub Pages 静态文件更新有约 30 秒 CDN 延迟 | 读数据必须走 GitHub API，不能读 Pages 上的静态副本 |
| iOS Safari 会清除 7 天未访问站点的 localStorage | 数据不能只存本地，必须落到 GitHub |
| iOS Safari 长按会先弹出系统菜单 | 编辑态用显式开关，不用长按手势 |

## 3. 整体架构

```
NFC 贴纸 (NTAG215)
  └─ 写入 URL: https://pyyannie.github.io/plants/?p=<代号>
        │
        ▼ 碰一下，点横幅
   Safari 打开 index.html
        │
        ├─ 读 ──▶ GitHub API: config.json / log.json
        └─ 写 ──▶ GitHub API: 提交一个 commit
```

没有服务器、没有构建步骤、没有依赖。单个 HTML 文件 + 两个 JSON 文件。

### 为什么用 GitHub 当数据库

- 每记一笔 = 一个 commit，白得一份带完整历史、可回滚的施肥流水
- 换手机、换电脑数据都在
- 不用自己搭服务器，也不用第三方服务

代价是需要一次性配置一个 token，见第 7 节。

## 4. 仓库结构

```
plants/
├── index.html      整个应用
├── config.json     植物名单 + 肥料名单
└── log.json        施肥流水
```

### config.json

```json
{
  "plants": {
    "guibeizhu": "龟背竹",
    "qinyerong": "琴叶榕"
  },
  "fertilizers": [
    { "name": "花多多#01", "hidden": false },
    { "name": "磷酸二氢钾", "hidden": false }
  ]
}
```

`hidden` 用于「删除」肥料按钮 —— 只从网格里隐藏，历史记录不受影响。

### log.json

```json
[
  { "p": "guibeizhu", "date": "2026-08-30", "fert": "花多多#01" },
  { "p": "qinyerong", "date": "2026-09-02", "fert": "磷酸二氢钾" }
]
```

一条记录三个字段，追加写入，不做修改。

## 5. 界面

### 5.1 单盆页面（带 `?p=` 参数）

```
┌──────────────────────────────┐
│  龟背竹                  ✏️编辑│
│  上次施肥 8/30 · 7 天前       │
│                              │
│  ┌────────────────────────┐  │
│  │  今天也施 花多多#01     │  │
│  └────────────────────────┘  │
│                              │
│  ── 或换个肥料 ──             │
│  ┌─────────┐  ┌─────────┐   │
│  │花多多#02 │  │磷酸二氢钾│   │
│  └─────────┘  └─────────┘   │
│  ┌─────────┐  ┌ ─ ─ ─ ─ ┐   │
│  │ 奥绿A2  │  │    ＋    │   │
│  └─────────┘  └ ─ ─ ─ ─ ┘   │
│                              │
│  历史                         │
│  8/30  花多多#01              │
│  8/02  花多多#02              │
└──────────────────────────────┘
```

规则：

- 顶部大按钮是「重复上次的肥料」，覆盖最常见的情况，一次点击完成
- 上次用过的那个肥料**不在下方网格里重复出现**
- 肥料按钮平铺，不折叠 —— 肥料种类少，折叠只是白白多一次点击
- 这盆植物从没记录过时，隐藏大按钮，只显示网格

### 5.2 首页（不带参数）

全部植物总览，按「距上次施肥的天数」从多到少排序 —— 越该施肥的排越前。点任意一盆进入单盆页面。

### 5.3 未登记的芯片

`?p=` 的代号在 `config.json` 里找不到时，页面显示「这盆还没名字，取一个？」，输入中文名后写入 `config.json`。

**这条是必须的**：15+ 盆植物，加一盆不能靠改代码。

## 6. 编辑行为

点右上角「✏️编辑」进入编辑态，每个肥料按钮角上出现 ✏️ 和 🗑，再点一次退出。

### 重命名

弹窗询问：「历史里的 N 条旧名字也一起改吗？」

- 选「是」：`log.json` 里所有该名字的记录一并替换（适用于改错字）
- 选「否」：只改 `config.json` 里的按钮名，历史保留旧名（适用于换了牌子）

### 删除

只把 `config.json` 里该肥料标记为 `hidden: true`，从网格里消失。**历史记录不动**，避免误删数据。

### 新增

网格末尾的虚线「＋」按钮，输入名字后追加到 `config.json`。

## 7. 认证与安全

页面通过 GitHub REST API 提交，需要一个 fine-grained personal access token：

- 权限范围：**只给 `pyyannie/plants` 这一个仓库**，只勾 `Contents: Read and write`
- 存放位置：手机 Safari 的 localStorage，**不进代码仓库**
- 首次打开页面时若无 token，显示配置引导

### 已知风险（已与用户确认接受）

1. **token 存在手机浏览器里** —— 手机被他人解锁时，对方可以改这个仓库。因为只是植物记录，风险可接受。前提是这个 token 不复用到其他仓库。
2. **仓库 public** —— 植物名和施肥记录公开可见。不敏感。
3. **提交邮箱** —— 仓库级 `user.email` 设为 GitHub 匿名邮箱 `143496086+pyyannie@users.noreply.github.com`，避免公开工作邮箱。全局 git 配置不动。

## 8. 需要处理的技术细节

### 写冲突

GitHub Contents API 更新文件需要带上当前文件的 `sha`。若两次提交撞在一起会返回 409，此时重新拉取最新 `sha` 并重试一次。单人使用极少触发，但必须处理，否则记录会静默丢失。

### 缓存

所有 API 读请求带 `Cache-Control: no-cache`，否则刚提交的记录读不到。

### 离线 / 失败

提交失败时明确告诉用户「没存上」，并保留他刚才的选择让他重试。**不能假装成功** —— 施肥记录记错比记不上更糟。

### 日期

用手机本地日期，格式 `YYYY-MM-DD`。不涉及时区换算。

---

## 9. 不做的事（YAGNI）

- 不记浇水、换盆、修剪 —— 用户明确只要施肥
- 不做提醒推送
- 不做多用户 / 登录
- 不做照片
- 不做施肥周期建议

---

## 10. 用户的一次性配置步骤

1. 建 GitHub 仓库 `pyyannie/plants`，push 代码，开 GitHub Pages
2. 生成 fine-grained token（按第 7 节的权限）
3. 手机打开 `https://pyyannie.github.io/plants/`，贴入 token
4. 装 NFC Tools，给每枚芯片写入对应网址
5. 每枚芯片碰一下，给植物取名

第 4、5 步每盆约 1 分钟。

### 贴纸注意

NTAG215 贴纸**不能直接贴金属花盆**，会读不到，需要垫一层防磁贴。陶土盆、塑料盆没问题。
