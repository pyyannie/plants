# 植物施肥记录 NFC 应用 — 设计文档

日期：2026-09-06（初版） / 2026-10-04（修订，见第 11 节）
代码仓库：`pyyannie/plants`（public，只放网页代码）
数据仓库：`pyyannie/plants-data`（**private**，放名单、记录、备注、照片）
线上地址：`https://pyyannie.github.io/plants/`

---

## 1. 要解决的问题

家里 30 多盆植物，记不清哪盆上次什么时候施的肥、施的什么肥，也想顺手记几句观察（比如「发现有虫」）。

目标体验：**用手机碰一下花盆上的 NFC 贴纸，立刻看到这盆植物上次施了什么肥、最新的备注，并能一键打卡。**

---

## 2. 硬约束

这些是系统层面的限制，方案必须绕开，不是可以商量的取舍。

| 约束 | 后果 |
|---|---|
| iOS 快捷指令的 NFC 自动化只能读芯片 UID，读不到写进芯片的内容 | 不走快捷指令，改为把网址写进芯片 |
| iOS 不允许 NFC 芯片里的网址无确认自动打开 | 碰完需要点一下顶部横幅，无法消除 |
| GitHub Pages 挂出来的网页一定是公开的（付费的 private 仓库也一样） | 网页代码和数据拆成两个仓库：代码 public、数据 private |
| private 仓库里的文件没有公开网址 | 数据和照片全部通过 GitHub API + token 读取，照片读出来转成本地图片地址再显示 |
| iOS Safari 会清除 7 天未访问站点的 localStorage | 数据不能只存本地，必须落到 GitHub |
| iOS Safari 长按会先弹出系统菜单 | 编辑态用显式开关，不用长按手势 |
| 手机原图 3–5 MB（且可能是 HEIC） | 上传前在网页里用 canvas 压到宽 800 px、JPEG 质量 0.7，约 100 KB |

## 3. 整体架构

```
NFC 贴纸 (NTAG216)
  └─ 写入 URL: https://pyyannie.github.io/plants/?p=<代号>
        │
        ▼ 碰一下，点横幅
   Safari 打开 index.html（来自 public 仓库 pyyannie/plants）
        │
        ├─ 读 ──▶ GitHub API: plants-data 的 config.json / log.json / photos/
        └─ 写 ──▶ GitHub API: 往 plants-data 提交一个 commit
```

没有服务器、没有构建步骤、没有依赖。

### 为什么用 GitHub 当数据库

- 每记一笔 = 一个 commit，白得一份带完整历史、可回滚的施肥流水
- 换手机、换电脑数据都在
- 不用自己搭服务器，也不用第三方服务

代价是需要一次性配置一个 token，见第 7 节。

## 4. 仓库结构

### 代码仓库 `pyyannie/plants`（public）

```
plants/
├── index.html
├── src/  logic.js  github.js  app.js
└── test/
```

不含任何植物名、记录或照片。别人打开网页，没有 token 只能看到配置页。

### 数据仓库 `pyyannie/plants-data`（private）

```
plants-data/
├── config.json     植物名单 + 肥料名单
├── log.json        打卡流水
└── photos/         每盆植物一张照片，文件名 = 植物代号
    └── 龟背竹.jpg
```

文件不存在时（新仓库）网页按空数据处理，第一次写入时自动创建。

### 植物代号与显示名

- **代号**写死在芯片网址里（`?p=龟背竹`），一旦写进贴纸就不变。直接用中文，`?p=` 参数会自动 URL 解码
- **显示名**存在 `config.json`，可以在网页上随时改（比如改成「龟背竹（阳台）」）
- 照片、记录都跟着代号走，改显示名不影响它们

### config.json

```json
{
  "plants": {
    "龟背竹": "龟背竹（阳台）"
  },
  "fertilizers": [
    { "name": "花多多01", "hidden": false },
    { "name": "花多多02", "hidden": false },
    { "name": "花多多08", "hidden": false },
    { "name": "花多多10", "hidden": false },
    { "name": "磷酸二氢钾", "hidden": false },
    { "name": "缓释肥", "hidden": false },
    { "name": "HB101", "hidden": false }
  ]
}
```

`plants` 是「代号 → 显示名」。`hidden` 用于「删除」肥料按钮 —— 只从网格里隐藏，历史记录不受影响。

### log.json

```json
[
  { "p": "龟背竹", "date": "2026-09-28", "fert": "花多多01", "note": "新叶有点黄" },
  { "p": "龟背竹", "date": "2026-10-02", "note": "发现有虫" }
]
```

- `fert`：施的肥。**没有这个字段 = 只记了备注，没施肥**
- `note`：备注，可选
- 一条记录至少有 `fert` 或 `note` 之一
- 追加写入，不做修改

## 5. 界面

### 5.1 单盆页面（带 `?p=` 参数）

```
┌──────────────────────────────┐
│  ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐  │
│  │    📷 点我加照片        │  │
│  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘  │
│  龟背竹                ✏️编辑 │
│                              │
│  🌱 上次施肥  9/28 · 6 天前   │
│     花多多01                  │
│  📝 最新备注  10/02           │
│     发现有虫                  │
│                              │
│  备注（可不填）                │
│  ┌────────────────────────┐  │
│  └────────────────────────┘  │
│  ┌────────────────────────┐  │
│  │       花多多01          │  │  ← 上次用的，大按钮
│  └────────────────────────┘  │
│  ┌─────────┐  ┌─────────┐   │
│  │花多多02  │  │花多多08  │   │
│  └─────────┘  └─────────┘   │
│  …                           │
│  ┌─────────┐  ┌ ─ ─ ─ ─ ┐   │
│  │ HB101   │  │    ＋    │   │
│  └─────────┘  └ ─ ─ ─ ─ ┘   │
│  ┌────────────────────────┐  │
│  │      只记备注            │  │
│  └────────────────────────┘  │
│                              │
│  历史                         │
│  10/02  📝 发现有虫           │
│  9/28   花多多01  📝 新叶有点黄│
└──────────────────────────────┘
```

规则：

- **照片区始终占位**。没照片时显示虚线框「📷 点我加照片」，点了调起 iPhone 的拍照/相册；有照片时编辑态下照片角上出现「换照片」
- 上传后立即显示手机本地那张，不等 GitHub
- 「🌱 上次施肥」只看带 `fert` 的记录；「N 天前」不会因为只记了备注而重算
- 「📝 最新备注」看最近一条带 `note` 的记录，不管那笔有没有施肥
- 如果最近一次施肥那笔本身就是最新备注，两行合成一块，不重复显示同一句
- 先在备注框里写字，再点肥料按钮 → 这一笔带上备注；点「只记备注」→ 只存备注。备注框为空时「只记备注」不可点
- 大按钮只写肥料名（不写「今天也施」），是上次施过的那个肥料；上次用过的那个不在下方网格重复出现
- 肥料按钮平铺，不折叠
- 这盆植物从没施过肥时，没有大按钮，只显示网格

### 5.2 首页（不带参数）

全部植物总览，按「距上次施肥的天数」从多到少排序 —— 越该施肥的排越前，从没施过的排最前。点任意一盆进入单盆页面。

### 5.3 未登记的芯片

`?p=` 的代号在 `config.json` 里找不到时，页面显示「这盆还没名字，取一个？」，输入中文名后写入 `config.json`。

## 6. 编辑行为

点右上角「✏️编辑」进入编辑态，再点一次退出。编辑态下点肥料按钮本体不打卡，避免误记。

### 植物改名

名字旁出现 ✏️，改的是 `config.json` 里的显示名，代号不变。

### 照片

照片角上出现「换照片」，新照片覆盖 `photos/<代号>.jpg`（旧照片留在 git 历史里）。

### 肥料重命名

弹窗询问：「历史里的 N 条旧名字也一起改吗？」

- 选「是」：`log.json` 里所有该名字的记录一并替换（适用于改错字）
- 选「否」：只改 `config.json` 里的按钮名，历史保留旧名（适用于换了牌子）

### 肥料删除

只把 `config.json` 里该肥料标记为 `hidden: true`，从网格里消失。**历史记录不动**。

### 肥料新增

网格末尾的虚线「＋」按钮，输入名字后追加到 `config.json`。

## 7. 认证与安全

页面通过 GitHub REST API 读写，需要一个 fine-grained personal access token：

- 权限范围：**只给 `pyyannie/plants-data` 这一个仓库**，只勾 `Contents: Read and write`
- 存放位置：手机 Safari 的 localStorage，**不进代码仓库**
- 首次打开页面时若无 token，显示配置引导

### 已知风险（已与用户确认接受）

1. **token 存在手机浏览器里** —— 手机被他人解锁时，对方可以读写数据仓库。因为只是植物记录，风险可接受。前提是这个 token 不复用到其他仓库。
2. **代码仓库 public** —— 只有网页代码，不含数据。
3. **提交邮箱** —— 代码仓库的仓库级 `user.email` 设为 GitHub 匿名邮箱 `143496086+pyyannie@users.noreply.github.com`。数据仓库虽然是 private，仍建议勾选 Keep my email address private。

## 8. 需要处理的技术细节

### 写冲突

GitHub Contents API 更新文件需要带上当前文件的 `sha`。若两次提交撞在一起会返回 409，此时重新拉取最新数据、把改动重新施加一遍再提交。

### 缓存

所有 API 读请求带 `Cache-Control: no-cache` 和 `cache: 'no-store'`，否则刚提交的记录读不到。

### 照片读取

Contents API 对 1 MB 以内的文件直接返回 base64 内容。压缩后的照片约 100 KB，远在限制内。读出来转成 Blob 再用 `URL.createObjectURL` 显示。

### 离线 / 失败

提交失败时明确告诉用户「没存上」，并保留备注框里的文字让他重试。**不能假装成功**。

### 日期

用手机本地日期，格式 `YYYY-MM-DD`。不涉及时区换算。

## 9. 不做的事（YAGNI）

- 不记浇水、换盆、修剪的专门按钮 —— 需要时写进备注
- 不做提醒推送
- 不做多用户 / 登录
- 不做施肥周期建议

## 10. 用户的一次性配置步骤

1. GitHub 设置里勾选 Keep my email address private
2. 建两个仓库：`pyyannie/plants`（public，推代码，开 GitHub Pages）和 `pyyannie/plants-data`（private，空的就行）
3. 生成 fine-grained token（按第 7 节的权限）
4. 手机打开 `https://pyyannie.github.io/plants/`，贴入 token
5. 装 NFC Tools，给每枚芯片写入对应网址
6. 每枚芯片碰一下，给植物取名、拍照

### 贴纸注意

NTAG216 贴纸**不能直接贴金属花盆**，会读不到，需要垫一层防磁贴。陶土盆、塑料盆没问题。
